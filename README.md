# DuoVoice Studio — دليل النشر

موقع بمتحدثين اتنين (Host / Guest) وألوان كريمي + تيل + مرجاني، فيه مدونة وصفحات قانونية. الصوت بييجي من **Azure AI Speech**، والتوليد مقفول بكلمة سر (للمالك بس).

## الهيكل (لازم يفضل كده بالظبط)
```
app.py
tts_engine.py
requirements.txt
render.yaml
README.md
static/
  index.html  how-to.html  about.html  contact.html  privacy.html  terms.html  shared.css
  blog/ (index.html + 3 مقالات)
  music/ (4 ملفات mp3 + manifest.json)
```
مفيش robots.txt ولا sitemap.xml جاهزين: السيرفر بيطلّعهم تلقائي بعنوان موقعك الحقيقي (/robots.txt و /sitemap.xml).

## 1) جهّز Azure Speech (مرة واحدة)
1. في portal.azure.com اعمل **Speech service** (Create a resource > Speech) بخطة **Free F0**.
2. اختار منطقة (Region) فيها الأصوات المتعددة اللغات، مثلا `eastus` أو `westeurope`.
3. من Keys and Endpoint خد **KEY 1** والـ **Region**.
4. الخطة F0 فيها نص مليون حرف مجانا في الشهر (أصوات Neural)، وبتقف لما تخلص بدل ما تخصم منك، بشرط ما تعملش ترقية لخطة مدفوعة.

## 2) النشر على Render
1. ريبو جديد على GitHub، وارفع **محتويات** الفولدر (مش الفولدر نفسه) بحيث `app.py` و`static/` في الجذر.
2. Render: New + > Web Service > الريبو. (الإعدادات جاهزة في `render.yaml`)
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn app:app --host 0.0.0.0 --port $PORT`
3. في **Environment** ضيف الـ 3 متغيرات دي (مهم):

| الاسم | القيمة |
|---|---|
| `AZURE_SPEECH_KEY` | مفتاح Azure |
| `AZURE_SPEECH_REGION` | مثلا `eastus` |
| `APP_PASSWORD` | كلمة السر اللي هتكتبها في خانة Access password |

4. بعد النشر: افتح الموقع، اكتب كلمة السر، وجرّب حلقة قصيرة.

**كلمة السر بتتحط في Render بس، مش في الكود ولا في GitHub.** لو `APP_PASSWORD` مش متحطة، التوليد بيفضل مقفول. بعد 8 محاولات غلط في الساعة من نفس الجهاز بيتحظر مؤقتا.

## متغيرات اختيارية (Environment في Render)
| الاسم | الافتراضي | الغرض |
|---|---|---|
| `MAX_SCRIPT_CHARS` | 20000 | أقصى طول للسكريبت |
| `GENERATE_LIMIT_PER_HOUR` | 12 | عدد التوليدات لكل زائر في الساعة |
| `TTS_CONCURRENCY` | 2 | عدد الطلبات المتوازية لخدمة الصوت (قلّلها لو ظهرت أخطاء 429) |
| `MONTHLY_CHAR_LIMIT` | 450000 | سقف الحروف الشهري للموقع (أقل من حصة Azure المجانية، 0 = بدون سقف) |
| `SITE_URL` | تلقائي | حطه (مثلا `https://yourdomain.com`) لو عندك دومين خاص |

## قبل تقديم AdSense
- [ ] جرّب توليد حلقة فعلا من الموقع المنشور (أداة مش شغالة = رفض محتمل).
- [ ] الأفضل دومين خاص (حوالي 10 دولار في السنة) بدل onrender.com.
- [ ] راجع بيانات التواصل في `static/contact.html` (الإيميل) وتواريخ الصفحات.
- [ ] اقرا الصفحات والمقالات بنفسك وعدّل بأسلوبك، المحتوى الأصلي هو الأهم.
- [ ] زوّد مقالات تدريجيا (كل مقال جديد = ملف html في `static/blog/` + سطر في `static/blog/index.html`).
- [ ] بعد الموافقة: الصق كود AdSense في `<head>` (فيه تعليق بيوريك المكان) وفعّل رسالة الموافقة (Privacy & messaging) من حساب AdSense، لأن سياسة الخصوصية بتقول إن الإعلانات المخصصة في أوروبا وبريطانيا بتظهر بعد الموافقة.
- [ ] بعد الموافقة أضف ملف `ads.txt` (AdSense بيديك السطر الجاهز).

## ملاحظات
- عدّاد الحروف الشهري محفوظ في ملف على الخادم، وفي الخطة المجانية على Render الملفات بتتمسح عند إعادة التشغيل، فالعدّاد ممكن يتصفّر. الحماية الحقيقية هي حصة Azure F0 نفسها.
- خطة F0 ليها حد على عدد الطلبات في الدقيقة، فالحلقات الطويلة ممكن تبطّأ والكود بيعيد المحاولة تلقائيا. لو كتر الـ 429 قلّل `TTS_CONCURRENCY` لـ 1.
- لو الأصوات متعددة اللغات (Multilingual) مش ظاهرة في القايمة، جرّب منطقة تانية.
- الخطة المجانية في Render بتنام بعد فترة خمول (أول زيارة بعدها بتاخد ~دقيقة)، والملفات المؤقتة بتتمسح بعد ساعتين.
- لو غيّرت الموقع ليبقى عام تاني (مثلا لـ AdSense)، شيل كلمة السر وراجع تكلفة الحروف الأول.
